The Stock Take Module is a facility available in SLiMS to assist librarians in carrying out collection inventory activities. This activity aims to re-adjust all collections in the library so that you can find out how many items are available, the number of items that are missing, the number of items that are damaged, and the items that are currently borrowed by library patrons.

When the inventory process starts, all items except those that are being borrowed (with the status “On Loan”) will be considered lost. Then enter the “Current Lost Item” sub-menu until the collection is entered in the exemplary data in the inventory process.

In this module, when the stock take process has not been activated, you will only find these 2 (two) menus:

  • Stock Take History
  • Initialize

The Stocktake History will list previous stocktakes by name [ the name for each stocktake being set when you initiate a stocktake], together with the Start and End Dates and the Report.

When you choose to initialise a stocktake, you’ll be prompted to make a backup if you have not done so. You should always backup before a stocktake.

You must provide a name for the stocktake, and you can then apply filters for GMD, Collection type, Location, Shelf location, and Classification, if you want to stocktake only part of your library. The default for these is ALL , which will produce a full stocktake.

Once initialised, the Initialise submenu will be replaced with submenu items:

  • Current stocktake : Allows entry of Item code . Clicking the Change status button will mark the item as not lost.
  • Stocktake report: Provides a comprehensive report on the stocktake including collection totals, losses, loans and personnel involved. Clicking the Download report button will produce a pop-up allowing printing , print to pdf etc.
  • Current lost item: Displays items that are currently marked as lost
  • Stocktake log: Provides a log of all Stocktake name consisting of time, user, and messages
  • Upload List: Allows upload of a plain text file (.txt) containing a list of item codes to stocktake; each item code on a separate line.
  • Resynchronise: Refreshes item data in the database. Resynchronise will only update the current stocktake’s item data. It won’t update any new title or item data that was inserted in the middle of the stocktake process
  • Finalise Stocktake. Does what it says. Once ended, the stocktake can’t be rolled back. An option to purge lost items from the collection is also presented. Backup the data base before committing to this.
